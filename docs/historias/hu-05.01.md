# HU-05.01: Publicação de vagas por professores

**Ator Principal:** Professor
**Módulo do Sistema:** Módulo de Interação
**Épico:** Épico 4 — Oportunidades e Interações
**Pré-condição:** O usuário deve estar autenticado no sistema e possuir perfil de professor.

---

## 1. Descrição Narrativa

> **Como** professor da plataforma,
> **gostaria de** criar uma publicação sobre uma nova oportunidade em projeto de pesquisa, extensão ou iniciação científica,
> **para** divulgar a vaga e encontrar alunos interessados em participar.

---

## 2. Checklist de Componentes da Interface (UI/UX)

### Elementos da página de criação de publicação

* [ ] Botão visível para criar uma nova publicação de vaga.
* [ ] Formulário de cadastro da oportunidade.
* [ ] Campo para título da vaga.
* [ ] Campo para descrição da oportunidade.
* [ ] Campo para informar área de interesse ou tema do projeto.
* [ ] Campo para informar requisitos desejáveis para os alunos interessados.
* [ ] Campo para anexar arquivos, caso necessário.
* [ ] Botão “Publicar” para finalizar a criação da vaga.
* [ ] Botão “Cancelar” para abandonar a criação da publicação.
* [ ] Indicação visual dos campos obrigatórios.

### Exibição da publicação

* [ ] Após publicada, a vaga deve aparecer na lista de oportunidades disponíveis.
* [ ] A publicação deve exibir título, nome do professor responsável, resumo da oportunidade e data de publicação.
* [ ] A publicação deve permitir que alunos visualizem mais detalhes sobre a vaga.
* [ ] Caso a publicação seja criada com sucesso, o sistema deve exibir uma mensagem de confirmação.

---

## 3. Critérios de Aceitação

### Fluxo Principal

#### Cenário 1: Publicação criada com sucesso

* **Dado** que o usuário está autenticado como professor,
* **E** está na página inicial ou na área de oportunidades,
* **Quando** ele clica no botão de nova publicação,
* **E** preenche corretamente o formulário de criação da vaga,
* **E** clica no botão “Publicar”,
* **Então** o sistema deve registrar a publicação no banco de dados,
* **E** tornar a vaga visível para os alunos na plataforma,
* **E** exibir uma mensagem de confirmação informando que a publicação foi criada com sucesso.

---

### Fluxos de Exceção

#### Cenário 2: Campos obrigatórios não preenchidos

* **Dado** que o professor está preenchendo o formulário de criação de vaga,
* **Quando** ele tenta publicar sem preencher um ou mais campos obrigatórios,
* **Então** o sistema deve impedir a publicação,
* **E** exibir a mensagem “Campo obrigatório não preenchido” próxima ao campo correspondente.

#### Cenário 3: Arquivo anexado em formato inválido

* **Dado** que o professor está criando uma publicação de vaga,
* **Quando** ele anexa um arquivo em formato não permitido,
* **Então** o sistema deve impedir o envio do arquivo,
* **E** exibir a mensagem “Arquivo em formato inválido”.

#### Cenário 4: Usuário sem perfil de professor tenta criar publicação

* **Dado** que um usuário autenticado não possui perfil de professor,
* **Quando** ele tenta acessar a funcionalidade de criação de vaga,
* **Então** o sistema deve restringir o acesso,
* **E** exibir uma mensagem informando que apenas professores podem publicar oportunidades.

---

## 4. Impacto Estrutural e Arquitetura de Dados

**Coleções/Entidades Afetadas:** `oportunidades`, `usuarios`, `professores`

**Considerações:**

* Cada publicação deve estar vinculada ao professor responsável.
* A entidade `oportunidades` deve armazenar informações como título, descrição, área de interesse, requisitos, professor responsável, data de criação e status da publicação.
* O sistema deve validar se o usuário possui perfil de professor antes de permitir a criação da vaga.
* A publicação deve ficar disponível para visualização pelos alunos após ser registrada com sucesso.
