# HU-01.03: Criar perfil de professor/pesquisador

**Ator Principal:** Professor/Pesquisador do departamento de Ciência da Computação da UnB

**Módulo do Sistema:** Módulo de perfil

---

### 1. Descrição Narrativa
> **Como** professor/pesquisador do departamento de Ciência da Computação da UnB,<br>
> **Gostaria de** criar meu perfil na plataforma Linka após meu primeiro acesso institucional,<br>
> **Para** promover e ofertar oportunidades de iniciação científica e pesquisa acadêmica.

---

### 2. Checklist de Componentes da Interface (UI/UX)
#### Dados pré-preenchidos automaticamente (vindos do login institucional — Épico 2, não editáveis)
- [ ] Exibição do nome completo do docente
- [ ] Exibição do e-mail institucional (@unb.br)
- [ ] Exibição da matrícula de discente
- [ ] Departamento de oriegem
- [ ] Titulação (Mestre / Doutor / Pós-Doutor)
#### Dados de contato (pelo menos um obrigatório)
- [ ] Campo: E-mail de contato alternativo (pode ser diferente do institucional)
- [ ] Campo: Telefone para WhatsApp (formato validado com máscara)
#### Perfil acadêmico
*(pré-preenchido pelos mecanismos do Épico 4 e editável manualmente para correções)*
- [ ] Campo: Link do currículo Lattes *(obrigatório)*
- [ ] Campo: Link do LinkedIn *(opcional, validado se preenchido)*
- [ ] Campo: Link do Google Scholar *(opcional, validado se preenchido)*
- [ ] Campo: Linhas de pesquisa *(texto descritivo, ao menos uma obrigatória)* — descreve em detalhe o foco investigativodo professor (ex: "Aprendizado por reforço aplicado a sistemas de recomendação")
- [ ] Campo: Disponibilidade para orientar novos alunos (Sim / Não / Apenas mestrado / Apenas doutorado)
#### Áreas de pesquisa (obrigatório indicar pelo menos uma)
Seleção múltipla com opções pré-cadastradas, como por exexmplo:
- [ ] Inteligência Artificial e Machine Learning
- [ ] Computação Teórica
- [ ] Engenharia de Software
- [ ] Segurança da Informação
- [ ] Interação Humano-Computador
- [ ] Desenvolvimento de Jogos
- [ ] Desenvolvimento Web e Mobile
- [ ] Banco de Dados
- [ ] Outras (com campo de texto livre)
#### Elementos de UX
- [ ] Indicador de progresso (ex: etapas "1 de 3")
- [ ] Botão "Salvar e continuar" ao fim de cada etapa
- [ ] Mensagens de erro inline por campo inválido
- [ ] Tela de confirmação com resumo do perfil criado e botão "Ir para meu perfil"
### 3. Critérios de Aceitação (Regras de Negócio e Validações)
#### Fluxo Principal (Sucesso):
* **Cenário 1: Criação de perfil com dados válidos**
- **Dado** que o professor acessou a plataforma pela primeira vez via conta institucional (Office 365),
- **Quando** ele preencher todos os campos obrigatórios corretamente e acionar "Confirmar",
- **Então** o sistema deve persistir o perfil com status ACTIVE, gerar um identificador único, exibir a telade confirmação e tornar o perfil visível na plataforma.
* **Cenário 2: Redirecionamento automático no primeiro acesso**
- **Dado** que o professor autenticou via Office 365 e ainda não possui perfil criado,
- **Quando** o login for concluído,
- **Então** o sistema deve redirecioná-lo automaticamente para o fluxo de criação de perfil, sem necessidade de navegação manual.
#### Fluxo de Exceção (Validações e Tratamento de Erros):
* **Cenário 1: Conta institucional inativa ou inválida**
- **Dado** que o professor tentou autenticar com uma conta sem vínculo ativo no departamento,
- **Quando** o sistema verificar o status com o Épico 2,
- **Então** o acesso deve ser bloqueado com a mensagem: *"Sua conta institucional não possui vínculo ativo. Entre em contato com a secretaria do CIC."*
* **Cenário 2: Campos obrigatórios não preenchidos**
- **Dado** que o professor tentou avançar no formulário,
- **Quando** houver campos obrigatórios em branco,
- **Então** o sistema deve destacar os campos com erro inline e impedir o avanço sem apagar dados já preenchidos.
* **Cenário 3: Formato inválido**
- **Dado** que o professor preencheu telefone ou link com formato incorreto,
- **Quando** o campo perder o foco ou o formulário for submetido,
- **Então** o sistema deve exibir mensagem de erro específica por campo (ex: *"Link do Lattes inválido. Use o formato: lattes.cnpq.br/..."*).
* **Cenário 4: Dado importado pelo Épico 4 com formato inválido**
- **Dado** que o Épico 4 populou um campo com dado em formato não reconhecido (ex: URL do Lattes malformada),
- **Quando** o professor acessar o perfil pela primeira vez,
- **Então** o sistema deve sinalizar o campo com aviso (ex: "Dado importado inválido — revise este campo") e permitir correção manual sem bloquear o restante do perfil.
