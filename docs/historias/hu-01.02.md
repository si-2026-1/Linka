# HU-01.02: Editar perfil de aluno

**Ator Principal:** Aluno do departamento de Ciência da Computação da UnB<br>
**Módulo do Sistema:** Módulo de Perfil<br>
**Épico:** Épico 1 - Perfis<br>
**Pré-condição:** Aluno já possui perfil criado (HU-01.01 concluída)

---

### 1. Descrição Narrativa

> **Como** aluno do departamento de Ciência da Computação da UnB,<br>
> **Gostaria de** editar meu perfil na plataforma Linka,<br>
> **Para** manter minhas informações atualizadas e aumentar minhas chances de ser encontrado por professores com oportunidades compatíveis com meu perfil.

---

### 2. Checklist de Componentes da Interface (UI/UX)
#### Dados institucionais *(exibidos, não editáveis)*
- [ ] Nome completo, e-mail institucional, matrícula, curso, período e nível de formação — exibidos em modo somente leitura com indicação visual desse status (ex: ícone de cadeado ou campo acinzentado)
#### Campos pessoais editáveis
- [ ] Campo: E-mail de contato alternativo 
- [ ] Campo: Telefone para WhatsApp (formato validado com máscara)
- [ ] Campo: Habilidades técnicas (tags livres)
- [ ] Campo: Link do currículo Lattes (validado se preenchido)
- [ ] Campo: Link do LinkedIn (validado se preenchido)
- [ ] Campo: Indicativo de disponibilidade para participar de oportunidades de pesquisa (Open to)
#### Áreas de interesse (obrigatório selecionar ao menos uma)
Seleção múltipla com opções pré-cadastradas, como por exexmplo:
- [ ] Inteligência Artificial e Machine Learning
- [ ] Computação Teórica
- [ ] Engenharia de Software
- [ ] Segurança da Informação
- [ ] Interação Humano-Computador
- [ ] Desenvolvimento de Jogos
- [ ] Desenvolvimento Web e Mobile
- [ ] Banco de Dados
- [ ] Outras (com campo de texto livre)
#### Elementos de UX *(adequados para fluxo de edição)*
- [ ] Formulário único com dados já preenchidos ao abrir a tela
- [ ] Botão "Salvar alterações" ao final do formulário
- [ ] Mensagens de erro inline por campo inválido
- [ ] Mensagem de sucesso após salvar (banner tipo toast "Perfil atualizado com sucesso")
- [ ] Data da última atualização exibida no topo da tela de edição
### 3. Critérios de Aceitação (Regras de Negócio e Validações)
#### Fluxo Principal (Sucesso):
* **Cenário 1: Edição com dados válidos**
- **Dado** que o aluno está autenticado e acessa a tela de edição do seu perfil,
- **Quando** ele alterar um ou mais campos e acionar "Salvar alterações",
- **Então** o sistema deve persistir as alterações e exibir confirmação de sucesso.
* **Cenário 2: Abertura da tela de edição**
- **Dado** que o aluno acessa a tela de edição,
- **Quando** a tela carregar,
- **Então** todos os campos editáveis devem estar pré-preenchidos com os dados atuais do perfil.

#### Fluxo de Exceção (Erros e Validações)
* **Cenário 1: Remoção de todas as áreas de interesse**
- **Dado** que o aluno desmarcou todas as áreas de interesse,
- **Quando** ele tentar salvar,
- **Então** o sistema deve exibir erro inline: *"Selecione ao menos uma área de interesse."* e impedir o salvamento.
* **Cenário 2: Formato inválido**
- **Dado** que o aluno preencheu telefone ou link com formato incorreto,
- **Quando** o campo perder o foco ou o formulário for submetido,
- **Então** o sistema deve exibir mensagem de erro específica por campo (ex: *"Link do Lattes inválido. Use o formato: lattes.cnpq.br/..."*).
