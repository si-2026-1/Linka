# HU-02.02: Diferenciação de papéis

**Ator Principal:** Sistema (automático após autenticação)

**Módulo do Sistema:** Módulo de autenticação

---

### 1. Descrição Narrativa
> **Como** sistema,  
> **Gostaria de** identificar automaticamente o papel do usuário autenticado,  
> **Para** liberar as funcionalidades e a interface correspondentes ao seu perfil (aluno, professor ou servidor).

---

### 2. Checklist de Componentes da Interface (UI/UX)
- [ ] Menu de navegação adaptado ao papel identificado
- [ ] Tela de revisão de cadastro para usuários com papel não identificado
- [ ] Indicação visual do papel do usuário no cabeçalho ou perfil

---

### 3. Critérios de Aceitação (Regras de Negócio e Validações)

#### Fluxo Principal (Sucesso):
* **Cenário 1: Papel identificado com sucesso**
  * **Dado** que o usuário autenticou com uma conta `@unb.br` válida,
  * **Quando** o sistema processar o token retornado pelo Office 365,
  * **Então** o papel (aluno, professor ou servidor) deve ser inferido e as permissões correspondentes liberadas automaticamente.

#### Fluxo de Exceção (Validações e Tratamento de Erros):
* **Cenário 2: Papel não identificado**
  * **Dado** que os dados retornados pelo Office 365 não permitem inferir o papel do usuário,
  * **Quando** o login for concluído,
  * **Então** o sistema deve direcionar o usuário a uma tela de revisão de cadastro para seleção manual do papel.
* **Cenário 3: Papel incompatível com a ação solicitada**
  * **Dado** que um aluno tenta acessar uma funcionalidade restrita a professores,
  * **Quando** a requisição for processada,
  * **Então** o sistema deve bloquear o acesso e exibir mensagem de permissão insuficiente.

---

### 4. Impacto Estrutural e Arquitetura de Dados

* **Entidades Afetadas:** `Usuario`
* **Atributos Modificados/Atualizados:**
  * `Usuario.papel`: definido como `aluno`, `professor` ou `servidor` após autenticação.
  * `Usuario.ativo`: validado como `true` para prosseguir com o acesso.
