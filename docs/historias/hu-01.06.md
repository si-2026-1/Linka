# HU-01.05: Editar perfil de grupo de pesquisa

**Ator Principal:** Professor/Pesquisador responsável pelo grupo <br>
**Módulo do Sistema:** Módulo de Perfil <br>
**Épico:** Épico 1 — Perfis <br>
**Pré-condição:** Grupo de pesquisa já possui perfil ativo (HU-01.05 concluída) e o professor autenticado é um dos
responsáveis pelo grupo. <br>

---

### 1. Descrição Narrativa
> **Como** professor responsável por um grupo de pesquisa,<br>
> **Gostaria de** editar o perfil do meu grupo na plataforma Linka,<br>
> **Para** manter as informações do grupo atualizadas e garantir que alunos encontrem oportunidades compatíveis com nossas linhas de pesquisa.

---

### 2. Checklist de Componentes da Interface (UI/UX)
#### Dados institucionais (exibidos, não editáveis)
- [ ] Identificador único do grupo 
- [ ] Data de criação do perfil na plataforma
#### Dados do grupo (editáveis)
- [ ] Campo: Nome do grupo de pesquisa
- [ ] Campo: Sigla do grupo
- [ ] Campo: Descrição geral do grupo *(texto livre)*
- [ ] Campo: Ano de fundação
- [ ] Campo: Departamento de origem
#### Vínculo institucional (editável)
- [ ] Campo: Professor(es) responsável(is) - ao menos um obrigatório em todo momento
#### Perfil acadêmico do grupo (editáveis)
- [ ] Campo: Link do diretório do grupo no CNPq
- [ ] Campo: Link do site oficial do grupo
- [ ] Campo: Linhas de pesquisa do grupo
#### Áreas de pesquisa (obrigatório manter ao menos uma)
- [ ] Inteligência Artificial e Machine Learning
- [ ] Computação Teórica
- [ ] Engenharia de Software
- [ ] Segurança da Informação
- [ ] Interação Humano-Computador
- [ ] Desenvolvimento de Jogos
- [ ] Desenvolvimento Web e Mobile
- [ ] Banco de Dados
- [ ] Outras (campo de texto livre)
#### Elementos de UX 
- [ ] Formulário único com dados já preenchidos ao abrir a tela
- [ ] Botão "Salvar alterações" ao final do formulário
- [ ] Mensagens de erro inline por campo inválido
- [ ] Indicador visual de campos alterados ainda não salvos
- [ ] Mensagem de sucesso após salvar
- [ ] Data da última atualização exibida no topo da tela
### 3. Critérios de Aceitação (Regras de Negócio e Validações)
#### Fluxo Principal (Sucesso):
* **Cenário 1: Edição com dados válidos**
- **Dado** que o professor responsável está autenticado e acessa a tela de edição do grupo,
- **Quando** ele alterar um ou mais campos e acionar "Salvar alterações",
- **Então** o sistema deve persistir as alterações, atualizar a data da última alteração e exibir confirmação de sucesso.
* **Cenário 2: Abertura da tela de edição**
- **Dado** que o professor responsável acessa a tela de edição,
- **Quando** a tela carregar,
- **Então** todos os campos editáveis devem estar pré-preenchidos com os dados atuais do grupo.
* **Cenário 3: Salvar sem alterações**
- **Dado** que o professor abriu a tela de edição sem modificar nenhum campo,
- **Quando** ele acionar "Salvar alterações",
- **Então** o sistema deve aceitar a ação sem erro e sem modificar a data da última alteração
* **Cenário 4: Adição de novo professor responsável**
- **Dado** que o professor seleciona um novo professor para ser corresponsável pelo grupo,
- **Quando** ele salvar as alterações,
- **Então** o sistema deve exibir o novo responsável no perfil do grupo.
#### Fluxo de Exceção (Validações e Tratamento de Erros):
* **Cenário 1: Tentativa de edição por professor não responsável**
- **Dado** que um professor autenticado tenta acessar a tela de edição de um grupo do qual não é responsável,
- **Quando** ele tentar acessar a tela,
- **Então** o sistema deve bloquear o acesso e exibir: *"Você não tem permissão para editar este grupo."*
* **Cenário 2: Remoção do único professor responsável**
- **Dado** que o grupo possui apenas um professor responsável,
- **Quando** o professor tentar se remover ou remover o único responsável da lista,
- **Então** o sistema deve bloquear a ação e exibir: *"O grupo deve ter ao menos um professor responsável."*
* **Cenário 3: Remoção de todas as áreas de pesquisa**
- **Dado** que o professor desmarcou todas as áreas de pesquisa,
- **Quando** ele tentar salvar,
- **Então** o sistema deve exibir erro inline: *"Selecione ao menos uma área de pesquisa."* e impedir o salvamento.
* **Cenário 4: Remoção de todas as linhas de pesquisa**
- **Dado** que o professor removeu todas as linhas de pesquisa,
- **Quando** ele tentar salvar,
- **Então** o sistema deve exibir erro inline: *"Informe ao menos uma linha de pesquisa."* e impedir o salvamento.
* **Cenário 5: Formato inválido em links**
- **Dado** que o professor preencheu link do CNPq ou site com formato incorreto,
- **Quando** o campo perder o foco ou o formulário for submetido,
- **Então** o sistema deve exibir mensagem de erro específica por campo.
