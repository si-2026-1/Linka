# HU-01.04: Editar perfil de professor/pesquisador

**Ator Principal:** Professor/Pesquisador do departamento de Ciência da Computação da UnB<br>
**Módulo do Sistema:** Módulo de Perfil<br>
**Épico:** Épico 1 - Perfis<br>
**Pré-condição:** Professor já possui perfil criado (HU-01.03 concluída)

---

### 1. Descrição Narrativa
> **Como** professor/pesquisador do departamento de Ciência da Computação da UnB,<br>
> **Gostaria de** editar meu perfil na plataforma Linka após meu primeiro acesso institucional,<br>
> **Para** manter minhas informações acadêmicas atualizadas e aumentar minha visibilidade para alunos que buscam oportunidades compatíveis com minhas linhas de pesquisa.

---

### 2. Checklist de Componentes da Interface (UI/UX)
#### Dados institucionais *(exibidos, não editáveis)*
- [ ] Exibição do nome completo do docente
- [ ] Exibição do e-mail institucional (@unb.br)
- [ ] Exibição da matrícula de discente
- [ ] Titulação (Mestre / Doutor / Pós-Doutor)
- [ ] Departamento de origem
#### Dados de contato (pelo menos um obrigatório)
- [ ] Campo: E-mail de contato alternativo (pode ser diferente do institucional)
- [ ] Campo: Telefone para WhatsApp (formato validado com máscara)
#### Perfil acadêmico
*(pré-preenchido pelos mecanismos do Épico 4 e editável manualmente para correções)*
- [ ] Campo: Link do currículo Lattes *(obrigatório)*
- [ ] Campo: Link do LinkedIn *(opcional, validado se preenchido)*
- [ ] Campo: Link do Google Scholar *(opcional, validado se preenchido)*
- [ ] Campo: Linhas de pesquisa *(texto descritivo, ao menos uma obrigatória)* 
- [ ] Campo: Disponibilidade para orientar novos alunos (Sim / Não / Apenas mestrado / Apenas doutorado)
#### Áreas de pesquisa (obrigatório indicar pelo menos uma)
Seleção múltipla com opções pré-cadastradas, como por exexmplo:
- [ ] Inteligência Artificial e Machine Learning
- [ ] Computação Teórica
- [ ] Engenharia de Software
- [ ] Segurança da Informação
- [ ] Interação Humano-Computador
- [ ] Desenvolvimento de Jogos
- [ ] Desenvolvimento Web e Mobile
- [ ] Banco de Dados
- [ ] Outras (com campo de texto livre)
#### Elementos de UX
- [ ] Formulário único com dados já preenchidos ao abrir a tela
- [ ] Botão "Salvar alterações" ao final do formulário
- [ ] Mensagens de erro inline por campo inválido
- [ ] Indicador visual de campos alterados ainda não salvos
- [ ] Mensagem de sucesso após salvar ("Perfil atualizado com sucesso")
- [ ] Data da última atualização exibida no topo da tela
### 3. Critérios de Aceitação (Regras de Negócio e Validações)
#### Fluxo Principal (Sucesso):
* **Cenário 1: Edição com dados válidos**
- **Dado** que o professor está autenticado e acessa a tela de edição do seu perfil,
- **Quando** ele alterar um ou mais campos e acionar "Salvar alterações",
- **Então** o sistema deve persistir as alterações e exibir confirmação de sucesso.
* **Cenário 2: Abertura da tela de edição**
- **Dado** que o professor acessa a tela de edição,
- **Quando** a tela carregar,
- **Então** todos os campos editáveis devem estar pré-preenchidos com os dados atuais do perfil, incluindo os importados pelo Épico 4.
#### Fluxo de Exceção (Validações e Tratamento de Erros):
* **Cenário 1: Remoção de todas as áreas de pesquisa**
- **Dado** que o professor desmarcou todas as áreas de pesquisa,
- **Quando** ele tentar salvar,
- **Então** o sistema deve exibir erro inline: *"Selecione ao menos uma área de pesquisa."* e impedir o salvamento.
* **Cenário 2: Remoção de todas as linhas de pesquisa**
- **Dado** que o professor removeu todas as linhas de pesquisa,
- **Quando** ele tentar salvar,
- **Então** o sistema deve exibir erro inline: *"Informe ao menos uma linha de pesquisa."* e impedir o salvamento.
* **Cenário 3: Formato inválido**
- **Dado** que o professor preencheu telefone ou link com formato incorreto,
- **Quando** o campo perder o foco ou o formulário for submetido,
- **Então** o sistema deve exibir mensagem de erro específica por campo (ex: *"Link do Lattes inválido. Use o formato: lattes.cnpq.br/..."*).
