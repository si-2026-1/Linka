    HU-05.04: Notificações sobre interações, comentários e mensagens

    Ator Principal: Aluno ou Professor Módulo do Sistema: Módulo de Interações Épico: Épico 4 — Oportunidades e Interações Pré-condição: O usuário deve estar autenticado no sistema e possuir conta ativa.

    1. Descrição Narrativa

    Como aluno ou professor cadastrado na plataforma, gostaria de receber notificações sobre novas publicações, interações, comentários ou mensagens relacionadas às oportunidades de meu interesse, para acompanhar atualizações importantes, responder conversas pendentes e me manter informado sobre projetos de pesquisa, extensão ou iniciação científica.

    2. Checklist de Componentes da Interface (UI/UX)

    Elementos da área de notificações

    • [ ] Ícone ou botão de notificações visível na interface principal do sistema.
    • [ ] Indicador visual de novas notificações não lidas.
    • [ ] Lista de notificações recebidas pelo usuário.
    • [ ] Exibição do tipo de notificação, como nova mensagem, novo comentário, nova publicação ou nova interação.
    • [ ] Exibição de data e horário da notificação.
    • [ ] Link ou redirecionamento para a publicação, conversa ou oportunidade relacionada.
    • [ ] Opção para marcar notificação como lida.
    • [ ] Diferenciação visual entre notificações lidas e não lidas.
    • [ ] Mensagem informativa caso o usuário não possua notificações.
    • [ ] Atualização da lista de notificações após nova interação relevante.

    3. Critérios de Aceitação

    Fluxo Principal

    Cenário 1: Notificação gerada com sucesso

    • Dado que um usuário está autenticado no sistema,
    • E existe uma ação relevante relacionada a ele, como nova mensagem, comentário, interação ou publicação de oportunidade,
    • Quando essa ação for registrada no sistema,
    • Então o sistema deve gerar uma notificação para o usuário destinatário,
    • E associar a notificação à oportunidade, publicação ou conversa correspondente,
    • E exibir a notificação na área de notificações do usuário,
    • E sinalizar visualmente que há uma nova notificação não lida.

    Fluxos de Exceção

    Cenário 2: Usuário acessa a área de notificações sem possuir notificações

    • Dado que o usuário está autenticado no sistema,
    • E não possui notificações registradas,
    • Quando ele acessa a área de notificações,
    • Então o sistema deve exibir uma mensagem informando que não há notificações disponíveis.

    Cenário 3: Notificação relacionada a uma oportunidade removida

    • Dado que o usuário possui uma notificação vinculada a uma oportunidade,
    • E essa oportunidade foi removida ou não está mais disponível,
    • Quando o usuário tentar acessar a notificação,
    • Então o sistema deve informar que o conteúdo relacionado não está mais disponível.

    Cenário 4: Marcação de notificação como lida

    • Dado que o usuário possui uma ou mais notificações não lidas,
    • Quando ele acessa a notificação ou escolhe marcá-la como lida,
    • Então o sistema deve atualizar o status da notificação,
    • E remover ou reduzir o indicador visual de notificações não lidas.

    Cenário 5: Falha ao carregar notificações

    • Dado que o usuário está autenticado no sistema,
    • Quando ele acessa a área de notificações,
    • E ocorre uma falha no carregamento dos dados,
    • Então o sistema deve exibir uma mensagem de erro,
    • E permitir que o usuário tente carregar as notificações novamente.

    4. Impacto Estrutural e Arquitetura de Dados

    Coleções/Entidades Afetadas: usuarios, notificacoes, oportunidades, mensagens, comentarios, interesses

    Atributos Modificados/Atualizados:

    • notificacaoId: identificador único da notificação.
    • usuarioDestinatarioId: identifica o usuário que receberá a notificação.
    • usuarioOrigemId: identifica o usuário que gerou a ação, quando aplicável.
    • tipoNotificacao: indica se a notificação se refere a mensagem, comentário, nova publicação ou demonstração de interesse.
    • oportunidadeId: identifica a oportunidade relacionada à notificação, quando aplicável.
    • mensagemId: identifica a mensagem relacionada à notificação, quando aplicável.
    • comentarioId: identifica o comentário relacionado à notificação, quando aplicável.
    • statusNotificacao: indica se a notificação está lida ou não lida.
    • createdAt: registra a data e o horário em que a notificação foi gerada.

    Considerações:

    • O sistema deve gerar notificações apenas para usuários relacionados à ação registrada.
    • O usuário deve conseguir diferenciar notificações lidas e não lidas.
    • As notificações devem direcionar o usuário para o conteúdo correspondente, quando este ainda estiver disponível.
    • Mensagens enviadas entre aluno e professor devem gerar notificação para o destinatário.
    • Interações de alunos em publicações de vagas podem gerar notificação para o professor responsável.
    • Novas publicações de professores seguidos podem gerar notificação para os alunos interessados.
    • O sistema deve tratar casos em que o conteúdo relacionado à notificação tenha sido removido ou encerrado.
