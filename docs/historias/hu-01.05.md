# HU-01.05: Criar perfil de grupo de pesquisa

**Ator Principal:** Professor/Pesquisador do departamento de Ciência da Computação da UnB<br>
**Módulo do Sistema:** Módulo de Perfil<br>
**Épico:** Épico 1 — Perfis<br>
**Pré-condição:** Professor já possui perfil ativo (HU-01.03 concluída)

---

### 1. Descrição Narrativa
> **Como** professor/pesquisador do departamento de Ciência da Computação da UnB,<br>
> **Gostaria de** criar um perfil para meu grupo de pesquisa na plataforma Linka,<br>
> **Para** divulgar as atividades do grupo, atrair alunos interessados e centralizar as oportunidades vinculadas ao grupo.

---

### 2. Checklist de Componentes da Interface (UI/UX)
#### Dados do grupo (obrigatórios)
- [ ] Campo: Nome do grupo de pesquisa
- [ ] Campo: Sigla do grupo *(ex: VisionLab)*
- [ ] Campo: Descrição geral do grupo *(texto livre)*
- [ ] Campo: Ano de fundação
#### Vínculo institucional (obrigatório)
- [ ] Campo: Professor(es) responsável(is) 
- [ ] Campo: Departamento de origem
#### Perfil acadêmico do grupo (opcionais)
- [ ] Campo: Link do diretório do grupo no CNPq
- [ ] Campo: Link do site oficial do grupo
- [ ] Campo: Linhas de pesquisa do grupo
#### Áreas de pesquisa (obrigatório selecionar ao menos uma)
- [ ] Inteligência Artificial e Machine Learning
- [ ] Computação Teórica
- [ ] Engenharia de Software
- [ ] Segurança da Informação
- [ ] Interação Humano-Computador
- [ ] Desenvolvimento de Jogos
- [ ] Desenvolvimento Web e Mobile
- [ ] Banco de Dados
- [ ] Outras (campo de texto livre)
#### Elementos de UX
- [ ] Indicador de progresso (ex: etapas "1 de 3")
- [ ] Botão "Salvar e continuar" ao fim de cada etapa
- [ ] Mensagens de erro inline por campo inválido
- [ ] Tela de confirmação com resumo do grupo criado e botão "Ir para o perfil do grupo"
### 3. Critérios de Aceitação (Regras de Negócio e Validações)
#### Fluxo Principal (Sucesso):
* **Cenário 1: Criação de grupo com dados válidos**
- **Dado** que o professor está autenticado e com perfil ativo,
- **Quando** ele preencher todos os campos obrigatórios e acionar "Confirmar",
- **Então** o sistema deve persistir o perfil do grupo com status ACTIVE, gerar um identificador único, vincular automaticamente o professor criador como responsável e tornar o grupo visível na plataforma.
* **Cenário 2: Grupo com mais de um professor responsável**
- **Dado** que o professor está criando o grupo,
- **Quando** ele selecionar mais de um professor responsável,
- **Então** o sistema deve registrar todos os vínculos e exibir todos os professores responsáveis no perfil do grupo.
#### Fluxo de Exceção (Validações e Tratamento de Erros):
* **Cenário 1: Tentativa de criação por não-professor**
- **Dado** que um usuário sem perfil de professor tenta acessar o fluxo de criação de grupo,
- **Quando** ele tentar acessar a tela de criação,
- **Então** o sistema deve bloquear o acesso e exibir a mensagem: *"Apenas professores podem criar grupos de pesquisa."*
* **Cenário 2: Nome do grupo já cadastrado**
- **Dado** que o professor preencheu o nome do grupo,
- **Quando** o sistema identificar que já existe um grupo com o mesmo nome no departamento,
- **Então** deve exibir aviso: *"Já existe um grupo com este nome no departamento. Deseja continuar mesmo assim?"*
* **Cenário 3: Campos obrigatórios não preenchidos**
- **Dado** que o professor tentou avançar no formulário,
- **Quando** houver campos obrigatórios em branco,
- **Então** o sistema deve destacar os campos com erro inline e impedir o avanço sem apagar dados já preenchidos.
* **Cenário 4: Formato inválido em links**
- **Dado** que o professor preencheu link do CNPq ou site com formato incorreto,
- **Quando** o campo perder o foco ou o formulário for submetido,
- **Então** o sistema deve exibir mensagem de erro específica por campo.
