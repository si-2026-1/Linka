# HU-01.08: Editar perfil de servidor do departamento

**Ator Principal:** Servidor Administrativo do departamento de Ciência da Computação da UnB<br>
**Módulo do Sistema:** Módulo de Perfil<br>
**Épico:** Épico 1 — Perfis<br>
**Pré-condição:** Servidor já possui perfil ativo (HU-01.07 concluída)

---

### 1. Descrição Narrativa

> **Como** servidor do departamento de Ciência da Computação da UnB,<br>
> **Gostaria de** editar meu perfil na plataforma Linka,<br>
> **Para** manter meus dados de contato e função atualizados, garantindo que professores e alunos consigam me localizar corretamente

---

### 2. Checklist de Componentes da Interface (UI/UX)

#### Dados institucionais (exibidos, não editáveis)
- [ ] Nome completo do servidor
- [ ] E-mail institucional (@unb.br)
- [ ] Matrícula funcional
- [ ] Departamento de vínculo
- [ ] Campo: Cargo
- [ ] Campo: Função exercida no departamento

#### Dados de contato *(pelo menos um obrigatório)*
- [ ] Campo: E-mail de contato alternativo
- [ ] Campo: Telefone para WhatsApp (com máscara de formato)

#### Elementos de UX 
- [ ] Formulário único com dados já preenchidos ao abrir a tela
- [ ] Botão "Salvar alterações" ao final do formulário
- [ ] Mensagens de erro inline por campo inválido
- [ ] Indicador visual de campos alterados ainda não salvos
- [ ] Mensagem de sucesso após salvar (ex: "Perfil atualizado com sucesso")
- [ ] Data da última atualização exibida no topo da tela

---

### 3. Critérios de Aceitação

#### Fluxo Principal (Sucesso)

* **Cenário 1: Edição com dados válidos**
- **Dado** que o servidor está autenticado e acessa a tela de edição do seu perfil,
- **Quando** ele alterar um ou mais campos e acionar "Salvar alterações",
- **Então** o sistema deve persistir as alterações, atualizar o campo de data da última atualização e exibir confirmação de sucesso.

* **Cenário 2: Abertura da tela de edição**
- **Dado** que o servidor acessa a tela de edição,
- **Quando** a tela carregar,
- **Então** todos os campos editáveis devem estar pré-preenchidos com os dados atuais do perfil.

* **Cenário 3: Salvar sem alterações**
- **Dado** que o servidor abriu a tela de edição sem modificar nenhum campo,
- **Quando** ele acionar "Salvar alterações",
- **Então** o sistema deve aceitar a ação sem erro e sem modificar o campo de data da última atualização.

#### Fluxo de Exceção (Erros e Validações)

* **Cenário 1: Campos obrigatórios removidos**
- **Dado** que o servidor apagou o conteúdo de um campo obrigatório,
- **Quando** ele tentar salvar,
- **Então** o sistema deve exibir erro inline no campo correspondente e impedir o salvamento.

* **Cenário 2: Formato inválido**
- **Dado** que o servidor preencheu o campo de telefone com formato incorreto,
- **Quando** o campo perder o foco ou o formulário for submetido,
- **Então** o sistema deve exibir mensagem de erro específica por campo.
