# HU-01.07: Criar perfil de servidor do departamento

**Ator Principal:** Servidor Administrativo do departamento de Ciência da Computação da UnB <br>
**Módulo do Sistema:** Módulo de Perfil<br>
**Épico:** Épico 1 — Perfis<br>
**Dependência:** Épico 2 (Autenticação via Office 365)

---

### 1. Descrição Narrativa

> **Como** servidor do departamento de Ciência da Computação da UnB,<br>
> **Gostaria de** criar meu perfil na plataforma Linka após meu primeiro acesso institucional,<br>
> **Para** gerenciar e manter atualizadas as informações institucionais do departamento ao qual estou vinculado.

---

### 2. Checklist de Componentes da Interface (UI/UX)

#### Dados pré-preenchidos automaticamente
*(vindos do cadastro institucional — Épico 2, não editáveis)*
- [ ] Nome completo do servidor
- [ ] E-mail institucional (@unb.br)
- [ ] Matrícula funcional
- [ ] Departamento de vínculo
- [ ] Campo: Cargo (ex: Técnico Administrativo, Secretário)
- [ ] Campo: Função exercida no departamento (ex: Coordenação de graduação, Apoio administrativo)

#### Dados de contato (pelo menos um obrigatório)
- [ ] Campo: E-mail de contato alternativo
- [ ] Campo: Telefone para WhatsApp (com máscara de formato)

#### Elementos de UX
- [ ] Indicador de progresso (ex: etapas "1 de 2")
- [ ] Botão "Salvar e continuar" ao fim de cada etapa
- [ ] Mensagens de erro inline por campo inválido
- [ ] Tela de confirmação com resumo do perfil criado e botão "Ir para meu perfil"

---

### 3. Critérios de Aceitação

#### Fluxo Principal (Sucesso)

* **Cenário 1: Criação de perfil com dados válidos**
- **Dado** que o servidor acessou a plataforma pela primeira vez via conta institucional (Office 365),
- **Quando** ele preencher todos os campos obrigatórios corretamente e acionar "Confirmar",
- **Então** o sistema deve persistir o perfil com status ACTIVE, gerar um identificador único e tornar o perfil ativo na plataforma.

* **Cenário 2: Redirecionamento automático no primeiro acesso**
- **Dado** que o servidor autenticou via Office 365 e ainda não possui perfil criado,
- **Quando** o login for concluído,
- **Então** o sistema deve redirecioná-lo automaticamente para o fluxo de criação de perfil, sem necessidade de navegação manual.

#### Fluxo de Exceção (Erros e Validações)
* **Cenário 1: Conta institucional inativa ou inválida**
- **Dado** que o servidor tentou autenticar com uma conta sem vínculo ativo no departamento,
- **Quando** o sistema verificar o status com o Épico 2,
- **Então** o acesso deve ser bloqueado com a mensagem: *"Sua conta institucional não possui vínculo ativo. Entre em contato com a administração do CIC."*

* **Cenário 2: Campos obrigatórios não preenchidos**
- **Dado** que o servidor tentou avançar no formulário,
- **Quando** houver campos obrigatórios em branco,
- **Então** o sistema deve destacar os campos com erro inline e impedir o avanço sem apagar dados já preenchidos.

* **Cenário 3: Formato inválido**
- **Dado** que o servidor preencheu o campo de telefone com formato incorreto,
- **Quando** o campo perder o foco ou o formulário for submetido,
- **Então** o sistema deve exibir mensagem de erro específica por campo.
